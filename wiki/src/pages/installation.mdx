# Installation

Open your project in your coding agent and send:

<CodeBlock wrapCode lang="text"><pre className="shiki css-variables" data-lang="text" tabIndex={0}><code><span className="line"><span>{installationPrompt}</span></span></code></pre></CodeBlock>

The agent clones the release tag, checks its version, copies the kit folder into place as an agent skill, and runs the
skill's setup. Setup detects React or plain HTML (and Tailwind v4), chooses your UI folder, copies the tokens,
loads them globally, and adds a pointer to `AGENTS.md`. It does not copy any component yet.
XRAY/DESIGN <code>{KIT_VERSION}</code> is current; existing installations stay on their version until explicitly upgraded.

## Start with natural language

Installation adds no commands. Ask:

```text
Add the segmented control for the period filter.
Build the settings screen with switches for lock and hidden balances.
Audit the send form against the design rules.
```

The agent reads `.agents/skills/design/RULES.md` before any UI work. Then it copies the components it needs into
your UI folder and adapts them there. Copied components are your code; the kit folder stays read-only.

## What gets installed

```text
.agents/skills/design/             # the kit: one folder, read-only, replaced on upgrade
├── SKILL.md                       # the agent skill: add, adapt, create, theme, upgrade, audit
├── RULES.md                       # design rules
├── VERSION
├── core/                          # shared code every component builds on
│   ├── tokens.css                 # tokens and cascade layers
│   ├── base.css                   # optional reset and focus ring
│   ├── tailwind.css               # optional Tailwind v4 bridge
│   └── motion.js                  # springs as linear(), indicator and FLIP helpers
└── components/<id>/               # COMPONENT.md, CSS, HTML, controller, React
.agents/design.lock.json           # version, UI folder, stack, and the components you use
<ui folder>/                       # core/ and the components you add, as your own code
```

The kit is the installed folder: there is no build, no package and no helper script. Components keep the
kit's folder layout inside your UI folder, so their relative imports keep working. A copied file counts as
unchanged while it is identical to its copy in the kit folder; that is how the agent knows what you have edited.
Nothing is added to `package.json`.

## Upgrade an existing installation

<CodeBlock wrapCode lang="text"><pre className="shiki css-variables" data-lang="text" tabIndex={0}><code><span className="line"><span>{upgradePrompt}</span></span></code></pre></CodeBlock>

Commit first: version control is the upgrade's rollback path. The agent keeps the old kit folder as the
merge base, then fetches the new release. Files you never changed are replaced; files you changed get a
3-way merge, and any conflicts are listed for the agent to resolve.

## Requirements

- Browsers: Baseline 2024 (Chrome and Edge 123+, Safari 17.5+, Firefox 128+). Newer features, such as anchor positioning and `@starting-style` exit transitions, degrade gracefully.
- React 19+ for the React versions. Plain HTML pages need no build step.
- Node 18+ for the skill's helper script. Without Node, the agent follows the same steps by hand.
- Claude Code reads skills from `.claude/skills/`; setup links the skill there when the project uses it.
